# 碎界 SHATTERVERSE

越打越离谱的肉鸽打砖块。Web 游戏，零运行时依赖：TypeScript + 自研 WebGL2 渲染管线 + Web Audio 合成音频。

**在线游玩：<https://ikaros-521.github.io/SHATTERVER/>** —— 推送 `main` 后由 GitHub Actions 自动构建并部署。

以「爽感」为核心设计目标：每一次击中都有反馈，构筑向 absurd（离谱）的方向无限生长，而屏幕即使被上百个球和连锁爆炸填满，也依然可读、依然 60 帧。

## 快速开始

需要 Node.js ≥ 20.19。

```bash
pnpm install        # 或 npm install
pnpm dev            # 开发服务器，默认 http://127.0.0.1:5173
pnpm build          # 类型检查 + 生产构建，输出到 dist/
pnpm preview        # 本地预览生产构建
pnpm test           # 单元测试 + 无头机器人平衡模拟
pnpm lint           # ESLint
pnpm format         # Prettier
```

`dist/` 是纯静态文件，可部署到任意静态服务器。

浏览器要求：支持 **WebGL2** 并开启硬件加速（Chrome / Edge / Firefox 最新版均可）。不支持时会显示明确的提示页。

## 玩法

- **球不会丢。** 落到底部的球稍后从挡板重新发射。用挡板的**不同位置**接球可以控制回弹角度；正中接球是「完美接球」，大量充能。
- **砖墙会下沉。** 沉过红色警戒线的砖块击碎一点护盾。护盾归零，本局结束。
- **弹幕用挡板拦截。** 炮台和 BOSS 发射的弹幕漏到底部才扣护盾，球和激光也能摧毁它。
- **每通过一关，三选一。** 碎晶可以刷新选项或跳过换取更多碎晶。
- **难度自选**：开局在「选择初始协议」界面选 5 档难度（标准 → 深渊）。档位加深砖墙下沉、砖块血量与数量，收窄挡板、压制球速、加密弹幕，困难以上出现会**吃球的湮灭砖**，深渊还会每 16 秒抹除一个多余的球。高档位得分 ×1.5 ～ ×4——排行榜的名次是用难度换来的。
- **战绩留在本地。** 每一局都会计入本地排行榜（主菜单「战绩排行」查看，按分数排名）；结算界面可以一键**保存战绩截图**——一张以最后画面为底、带全部数据与最终构筑的分享卡片 PNG。
- 集齐两种元素会自动解锁**元素反应**：融化（冰+火）、过载（火+雷）、超导（冰+雷）、剧爆（毒+火）。

## 设计支柱

1. **爽感优先。** 顿帧、创伤式震屏、弹簧变焦、慢动作、冲击波折射、随连击升调的合成音效——每一次击中都是一次小型演出。
2. **离谱但可读。** 构筑可以走到 18 个球、连锁超新星、黑洞、时停同时在场。所有大范围特效都带预算与封顶（每帧爆炸配额、HDR 压缩、伤害数字合并），奇观不会退化成白屏。
3. **决策有深度。** 抽卡向已有体系倾斜但不强制；传说与神话是构筑的终点而非运气。

## 技术架构

模拟与表现严格分离。`src/game/` 不依赖 DOM 和 WebGL，可在 Node 中无头运行——单元测试、平衡模拟和浏览器跑的是同一份代码。

```
src/
  core/        RNG（可复现种子）、事件总线、数学、存档
  game/        纯逻辑：世界模拟、物理、伤害管线、升级、关卡生成、会话
  render/      WebGL2 渲染器、SDF 实例化着色器、后处理、特效导演、镜头
  audio/       Web Audio 合成引擎、音效配方、程序化音乐、音频导演
  ui/          DOM 界面：HUD、抽卡、图鉴、结算、设置
  app.ts       应用层：状态机、输入、主循环
```

- **模拟**：扫掠圆与 AABB 的连续碰撞检测（再快的球也不会穿透），死亡效果走队列所以连锁反应是迭代而非递归，伤害来源分为球 / 次级 / 持续 / 范围以控制触发链。
- **渲染**：所有场景物体都是同一段实例化 SDF 着色器中的实例，每个混合模式一次绘制调用；整帧共约 10 次绘制。HDR 浮点渲染目标 → 提亮 → 两级高斯模糊 → 合成（Bloom、色散、冲击波折射、引力透镜、径向模糊、故障、ACES 色调映射、暗角、颗粒）。
- **音频**：没有任何音频文件。音效是振荡器与滤波噪声的配方，音乐是按帧向前调度的 16 步音序器，混响来自程序生成的脉冲响应。音序器的前瞻窗口为 450ms，并有一个慢速定时器兜底喂入——动画帧被系统节流（通知横幅、切后台）时音乐不会断；音频上下文被打断（来电、闹钟）后自动恢复。**帧率高低从不影响音效**：音频跑在独立线程上，砍音效换不来流畅，只会丢掉反馈。
- **自适应画质**：特效层统计每帧事件量，自动收敛发射量并合并伤害数字。其上是画质调节器（`src/render/governor.ts`）：以 100 帧为一个判断窗，若超过八成的帧迟到（低于约 36 帧/秒），就沿「高 → 中 → 低 → 低（75% 渲染分辨率）」降一级——在高密度屏幕上每级约减少一半像素，而像素数正是 GPU 耗时的主导量。**每一级都必须证明自己有用**：降级后的那个窗口，平均帧时间要比触发降级的窗口短 15% 以上才算数，才会为这台设备记住（下次直接从这里开始）；连续降级毫无改善，则判定帧率并非由 GPU 决定（典型是系统省电模式把页面锁在 30 帧），恢复玩家选择的画质并停止自动调整。设置页会说明当前实际生效的档位。
- **静止画面低频重绘**：暂停、抽卡、结算时画面不动，这些界面只以约 15 帧/秒重绘，手机不会在一层对话框后面持续发热，把温度余量留给接下来的战斗。

### 平衡方法

`tests/balance.test.ts` 让内置机器人（近乎完美地接球和拦截弹幕）以四种选牌人格各打 8 局完整战役，输出每关耗时的中位数 / P95 / 最大值与受伤统计，并对节奏设回归断言。机器人是上限，选牌人格代表玩家构筑水平。当前结果：第 1 关约 17 秒，通关一局约 5 分钟，四种人格的通关率分别为 75% / 63% / 75% / 75%。

### 调试接口

页面暴露 `window.__shatterverse`，用于自动化检查和调参：

| 方法                                   | 说明                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `state()`                              | 当前状态快照（关卡、连击、BOSS、绘制统计、帧率、音频状态……）                                             |
| `advance(seconds)`                     | 不依赖实时帧推进模拟并绘制一帧                                                                           |
| `freeze(on)`                           | 冻结模拟，用于截取精确的某一帧                                                                           |
| `autopilot(on)`                        | 让内置机器人接管挡板                                                                                     |
| `start(mode, starter, level?, build?)` | 开启一局，可指定起始关卡与初始构筑（跳关的局不计入纪录）。协议 id：`blank` `barrage` `battery` `element` |
| `grant(id, levels)`                    | 给当前局发放强化                                                                                         |
| `lose()`                               | 耗尽当前局的护盾，直接进入结算流程                                                                       |
| `scorecard()`                          | 合成战绩截图（不下载），返回尺寸、字节量与 data URL，供检查                                              |
| `profile(frames?)`                     | 各渲染通道的 GPU 耗时（ms，中位数）及合计。每通道后强制等待 GPU，会卡住管线，只用于诊断                  |
| `perf()`                               | 最近若干秒的帧率统计（平均 / 低帧 5% / 卡顿占比）与当前实际生效的渲染档位                                |
| `autoPause(on)`                        | 开关失焦自动暂停                                                                                         |
| `audio()`                              | 输出电平（峰值 / RMS）                                                                                   |
| `errors`                               | 未捕获的错误列表，应保持为空                                                                             |
| `cloud()`                              | 云榜身份（`playerId`、昵称、昵称是否待生效）；本构建未配置凭据时为 `null`                                |

`state()` 里的 `quality` / `renderScale` / `qualityAdjusted` 是实际生效的档位，而不是设置里的偏好。

### 在真机上定位性能问题

设置页底部有「性能诊断」：实时显示平均帧率、最差 5% 帧的平均帧率与卡顿占比；「检测渲染耗时」会量出一帧里 GPU 时间在各通道的分布（合成 / 背景 / 光效 / 砖与球 / 泛光 / 星云 / 数字）。手机上卡顿时，把这两行数字记下来就足以定位方向。

## 云端排行榜

本地榜单之外，成绩会同步到 [CheddaBoards](https://docs.cheddaboards.com/quickstart/rest) 的云榜（Game ID `shatterver`）。整条链路是**尽力而为**的：网络失败、限流、成绩被拒都只会在结算页显示一行提示，本局记录照常写进本地榜单。

- **每局自动上传**：开一局时向服务端开一个 play session，结算时提交分数与最高连击，然后关闭 session。开着校验时这套流程直接可用；关着时它只是空转，不会影响任何一局。
- **昵称**：菜单「云端排行榜」里设置。服务端只接受 `3–16` 位 `A-Z a-z 0-9 _`（中文、空格、表情会被拒），重名会自动加数字后缀，页面显示的永远是服务端实际生效的名字。新玩家的昵称会挂起到第一次提交成绩时生效；若到时已被占用，客户端会自动重发改名，拿到带后缀的名字。
- **违规昵称**：本地先过一遍 `src/net/nickname.ts`，词表在 `blocklist.ts`（色情、毒品、赌博、歧视与仇恨、涉政等）。匹配前会做 NFKC 归一、去零宽字符、去分隔符、折叠 leet 与重复字母，所以 `f_u_c_k`、`sh1t`、`fuuuck`、全角字母都能拦住；短词只按整名匹配，`Cass`、`Sussex`、`Grape` 不受影响。词表是起步集，运营某市场时应按法务给的清单扩充。
- **难度与模式**：`POST /scores` 没有自定义字段，因此这两项只能靠**定向榜**承载。需要在开发者控制台（Scoreboards → Board Type: **Targeted**）创建下列 ID，创建后客户端会自动识别并向对应榜提交、在云榜页显示；缺失时静默跳过，不会每局撞 404：

  | Board ID                       | 含义           |
  | ------------------------------ | -------------- |
  | `mode-campaign`                | 闯关模式       |
  | `mode-endless`                 | 无尽模式       |
  | `diff-standard` … `diff-abyss` | 五档难度各一个 |

- **总榜是混合难度的**：难度加成最高 ×4，所以「总榜」只适合看最强纪录；同难度对比看上面的难度榜。
- **唯一值**：昵称由服务端保证唯一，客户端不维护昵称注册表。
- **凭据**：Game ID 与 API Key 在 `src/net/config.ts`，可用 `VITE_CB_GAME_ID` / `VITE_CB_API_KEY` 覆盖；把 Key 置空即可整体关闭云榜（菜单入口同时消失）。API Key 按设计是公开的：它会随构建产物下发，不能读私有数据、不能改游戏。
- **隐私**：匿名游玩只上传随机设备 ID、昵称、分数、最高连击与场次；不采集邮箱、位置或广告标识。见 [CheddaBoards 隐私政策](https://cheddaboards.com/privacy)。

## 已知限制

- **手感未经真人试玩验证。** 数值来自机器人模拟，机器人的接球与拦截近乎完美，真人的实际难度会更高；首次上手感是最重要的一步。
- **音频只验证了“有输出且不削波”**（实测峰值 0.72、平均 RMS 0.08），音色与混音未经人耳调校。
- 手机竖屏已完成布局适配（390px 宽验证过全部界面）；触屏样式、画质调节器的判定逻辑均有测试覆盖。但**真机上的帧率没有实测过**：开发机是桌面显卡，只能按手机的像素预算做代理测量（结论是 GPU 耗时随像素数线性变化、各通道占比均匀，所以降分辨率是主要手段）。真机表现请以设置页的「性能诊断」为准。
- 画质调节器只会降、不会升：设备变快后（比如关掉省电模式）保持已记住的档位，需在设置里手动调高。
- 存档使用 `localStorage`，本地榜单只保留最近 50 局且只记录本机成绩；云端榜单是另一份数据（见上文），两者不合并：云榜只保留每位玩家的最好成绩。
