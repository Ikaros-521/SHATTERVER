# 图组 Boss：一个角色每个阶段换一张图

第 10 关的「星炉占星师·薇斯珀」是第一个**图组 Boss**：不拆层、不做部件动画，她就是一整张画，
战斗打到哪儿就换成哪张——完好、破损、更破损……到最后一张打空才倒。

这是最省事也最好看的做法：美术出图，程序只负责「抠图、对齐、换图」。这篇文档讲怎么加下一个。

## 一、要准备什么

**一个文件夹的透明 PNG，一张图一个阶段，从 `1` 开始编号**：

```
art-src/boss/<id>/
  1.png   完好
  2.png   第一档破损
  …
  6.png   最后一档（打空这张她才倒）
```

- 每张一个独立的人物，透明背景（自己抠好，或用没切开的拼图——见第四节）。
- **同一个人物、同一个姿势系列**，眼睛的位置不用对齐——工具会按眼睛自动对齐。
- 想要几档就几张；4~6 张比较合适。
- 眼睛的颜色要和画面里别的东西**不一样**（薇斯珀是橙金色瞳）。工具靠找眼睛来对齐，
  找不到时会报错并告诉你怎么手动指定。
- 原图不进仓库（`art-src/` 被 `.gitignore` 挡着，太重）。自己留一份。

出图建议：用同一张立绘做局部重绘 / 局部修改，别每张独立生成——人物会跑。

## 二、三步接进游戏

### 1. 切图

```sh
python tools/boss-cut/stages.py art-src/boss/<id> src/render/boss/<id> --id <id> --preview /tmp/<id>
```

需要 Python 3.10+ 与 numpy、scipy、Pillow（项目自己的工具链不依赖它们，脚本也不进任何包）。

它会生成：

| 文件               | 内容                                                         |
| ------------------ | ------------------------------------------------------------ |
| `art/stage-N.webp` | 每个阶段一张图（已对齐、底部渐隐、压好）                     |
| `art/glow-N.webp`  | 每张图的光晕                                                 |
| `layout.ts`        | 每张图在人物坐标系里的位置，以及**打击区**（哪些位置能被打） |
| `art.ts`           | 加载这些图的页面                                             |

`--preview` 会写一张 `preview.png`：六张图排在夜空底上，青色圈是打击区。**先看这张**，
圈没盖到的地方球会穿过去。

`layout.ts` 和 `art.ts` 是生成物，不要手改。

### 2. 写战斗定义 `src/game/<id>.ts`

照 `src/game/vesper.ts` 抄一份，改三处：

```ts
export const WHOEVER: CharacterDef = {
  id: 'whoever',                 // 和文件夹名一致
  name: '她的名字',               // 结算页、历史记录用的名字
  parts: partsOf(),              // 照抄，改里面的 REGION 表（每个区域耐打多少、占多重）
  core: null, shield: null,      // 图组 Boss 没有护盾/星核
  stages: { until: [0.84, 0.68, 0.5, 0.32, 0.16] },   // 6 张图 = 5 个门槛
  phases: [0.5, 0.32, 0.22],     // 阶段按血条切（见第三节），图组 Boss 必写
  figure: 1.9,                   // 她多大（1.9 ≈ 占场上部一半宽；半身像用这个，全身像用 1.2 左右）
  x: ARENA_W / 2, y: 290,        // 站在哪（y 是眼睛的高度）
  …                                 // 进攻、回炉、颜色照旧
};
```

- `stages.until`：完整度掉到每个门槛就换下一张图。张数 = 数组长度 + 1。
- `REGION`：工具把打击区按**头 / 上身 / 裙摆 / 左右侧**分成 5 个区域，每个区域给耐打和重量。
  怎么定这两个数见第六节——别照搬绯樱的思路只堆耐打。

### 3. 登记三处

- `src/game/characterBoss.ts` 的 `CAST`：把她放进对应的 Boss 槽位（第 5 / 10 / 15 关）。
- `src/app.ts`：`this.boss.register(<id>, stageSource(load<ID>, <ID>_STAGES, <id>Motion, <id>.figure))`，然后 `void <source>.preload()`。
- `src/i18n/{zh,en,ja,ko}.ts` 的 `characterBoss.<id>`：名字、称号、代号、装甲条标注、六句台词——
  **守 `AGENTS.md` 第二节的每一条红线**。

## 三、规则是怎么跑的

- **战斗和拆件版是同一套**：打击区各有耐打值，磨穿了就没了；耐打值按重量合成「完整度」。
  耐打按**挨了几下**算，不看伤害：多球构筑克她，纯加伤害的构筑只是计分更多。
- **换图是结果**：完整度掉到门槛 → `state.stage` 变成下一张 → 渲染层交叉淡入 0.45 秒，
  换图那一刻有一记短亮闪。
- **打击区跟着图走，画到才打得着**：`layout.ts` 每行打击区末尾的数组是「被哪几张图画到」。
  星炉只在画它的图里是实体；灯炉那一侧要到第 5、6 张图才出现，之前的图里球从那儿直接穿过，
  所以只在后几张图出现的道具**不会在开局就被流弹打掉**。
  `tests/vesper.test.ts` 逐个子集守着「无论还剩哪几个区域，它们加起来对应的那张图里总有一个能打」，
  不会出现打不死的情况。
- **出招的位置不看图**：她还站着的部位就能出招，哪怕当前这张图没画它。薇斯珀的齐射来自
  灯炉那一侧，第 1~4 张图没画灯炉，齐射照样从那儿出来——只有球会被「画没画」挡住。
  部位被打掉后才既不能挨打也不能出招。
- **阶段按血条切**（`phases`）：绯樱那种十个小部件的 Boss，阶段按「整块脱落的重量」切没问题；
  图组 Boss 只有五个大区域，用那套会卡在第二阶段（打掉 84% 还算第二阶段，残血招放不出来）。
  所以图组 Boss 写 `phases: [p2, p3, p4]`，按玩家看得见的血条切，通常和换图门槛对齐。
- **攒到阶段的招**：`phase: 4` 的招在阶段到来时**第一个放**（1 秒内），不用等轮次；
  加 `once: true` 就整场只放一次。薇斯珀的 8 连发两者都带。
- **受击**：整张图取所有区域里最重的一击，再乘 `flash`（薇斯珀 0.14）。她每秒挨好多下，
  一整张图被每一击都点亮就全是白了——所以这个数要小。

## 四、没切开的拼图也行

`stages.py` 也能吃一张拼好的大图（3×2 排布的六格图）：整张抠图，按「连在一起的东西」分成六份，
每份归到它重心所在的格子里。不需要给切线，各格的图可以越过格线。

```sh
python tools/boss-cut/stages.py sheet.png src/render/boss/<id> --id <id> --rows 3 --cols 2
```

- 右下角有「AI 生成」水印的，用 `--blank x0,y0,x1,y1` 把它当纸抠掉。
- 眼睛找不到：`--eyes "x,y;x,y|x,y;x,y|…"`（每格一对，用 `|` 隔开，坐标是整张拼图的像素）。
- 细长的小道具（提灯本体、法杖）盖不满一个圆盘，工具不会给它单独放打击区——打击区落在
  它旁边的衣摆 / 发梢上。薇斯珀的「右侧」就是灯炉旁边的发梢，不是灯炉本身。

## 五、审核上的注意

图上**不要有血**。薇斯珀的后两张图（脸和手臂上的血迹）在 `AGENTS.md` 的图片红线上有风险
（死亡 / 暴力意象，会被 OCR 和人工审核看到）。我试过按颜色自动识别血迹改成金色，不可靠
（肤色阴影、帽檐内侧的红光和血色相重叠）。要上线，请把这两张重出一版无血的，或者在提审前
确认平台接受。第 5、6 张图目前照原样在游戏里。

## 六、调数值

| 要调什么                     | 在哪                                                |
| ---------------------------- | --------------------------------------------------- |
| 她多大、站哪                 | `src/game/<id>.ts` 的 `figure` / `x` / `y`          |
| 多耐打、哪个区域多重         | 同上，`REGION`                                      |
| 什么时候换图                 | 同上，`stages.until`                                |
| 什么时候换阶段               | 同上，`phases`                                      |
| 进攻节奏与招式               | 同上，`attackCd` / `attacks`                        |
| 换图快慢                     | `src/game/characterBoss.ts` 的 `stageFade`          |
| 摆动、光、受击多亮、换图多亮 | `src/render/boss/<id>/motion.ts`                    |
| 打击区的大小和分区           | `tools/boss-cut/stages.py` 的 `REGIONS` 与 `radius` |

**耐打别拍脑袋，用机器人校**。薇斯珀第一版给了 912 下，是绯樱（最终 Boss，294 下）的三倍，
第 10 关一局机器人要打 215 秒——玩家自己打更久。现在 210 下，机器人中位 65 秒。
`tests/boss-balance.test.ts` 用机器人从第 1 关正常打到第 10 关（带真实构筑），守住：

- 每局都打得过，且不超过两分钟；
- 4 球构建的中位时长（这是大多数构筑；8 球构建大约快一半）；
- 残血连发每局恰好放一次。

定数值时看三件事（`tests/sim.ts` 的 `sensible` 策略 + `Session(..., { characterBoss: true })` 就能跑）：

1. **球打在哪**。球从下面来，先撞裙摆；头和上身要绕过裙摆才打得到，命中率只有裙摆的三四成。
   所以头和上身的耐打要**低于**裙摆——否则裙摆掉了以后还剩一大截头身要慢慢磨，尾段又臭又长。
2. **重量跟着耐打走**（`weight ∝ hp`）：这样每挨一下掉的血条一样多，换图节奏才均匀，
   不会因为玩家瞄哪里而忽快忽慢。
3. **两侧的道具要脆**。它们小、又只在部分图里出现，耐打高了整场架有一半时间在追着打它们。

参考：薇斯珀 头 36 / 上身 42 / 裙摆 120 / 两侧各 9，第 10 关机器人中位 65 秒
（第 5 关砖阵 Boss 约 25 秒，第 15 关绯樱约 150 秒）。

## 七、加一种招式 / 加一种弹丸（`src/game/bossShots.ts`）

一个招式是 `attacks` 里的一行数据：

```ts
{ kind: 'volley', from: ['side.R'], shots: 2, phase: 4,
  shot: { speed: 340, radius: 11, visual: 'shard', damage: 2, fuse: 1.2 } }
```

- `kind`：投放图案，注册表 `PATTERNS` 里的键。现有 `volley`（每个部位朝挡板齐射）、
  `orb`（单个慢速大球）、`rain`（横排下落）。**加一种投放 = 注册表加一个函数**，只拿到
  「发射场」（挡板位置、随机数、容量、spawn），碰不到战斗状态。
- `shot`：弹丸规格——速度（缺省用图案自己的节奏）、半径、`visual`（外观画师的键）、
  `fuse`（爆裂引信秒数，爆出 `scatter` 发）、`damage`（落底扣几格，缺省 1）。
- `scatter` / `scatterLate`：爆裂数（后期更宽）；`phase`：阶段未到时这招被跳过，阶段一到
  **第一个放**；`once: true`：整场只放一次。
- **加一种弹丸外观 = `src/render/scene.ts` 的 `SHOT_PAINTERS` 加一个画师**——不一定是圆形：
  `star`（十字星）、`shard`（沿速度方向的长条）都在那里，照抄改形状即可。

要看行为，`tests/boss-shots.test.ts` 用一个记录用的发射场逐个图案断言。

调试图：`__shatterverse.character({}, 3)` 直接看她第 4 张图（配 `freeze(true)` 截图）；
`__shatterverse.character()` 读完整度、当前图号、淡入进度、打击区数量与图集情况。

## 八、相关的守门

- `tests/vesper.test.ts`：换图 Boss 的战斗与接线（门槛换图、打击区跟图走且打得完、阶段、进攻、残血连发）。
- `tests/character-boss.test.ts`：战斗本身的数学（磨损、阶段、攒招、出招位置）。
- `tests/boss-stage.test.ts`：换图模板（交叉淡入、亮闪、缺图不画、六张图对齐）。
- `tests/boss-balance.test.ts`：机器人打整场，守住第 10 关的时长与残血连发。
- 实机上着色器编译失败只有真 GPU 能抓到——`__shatterverse.errors` 应当为空。
